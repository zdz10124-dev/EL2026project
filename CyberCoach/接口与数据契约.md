# 赛博教练接口与数据契约（v1 草案）

## 1. 目标与范围
本文件用于前后端联调与测试，覆盖以下能力：
1. 运动记录（手动录入）
2. OCR 识别草稿
3. 单次报告生成
4. 周报生成
5. 训练计划生成
6. 提醒设置

说明：当前为 MVP 草案，优先保证字段稳定和可测性。

## 2. 通用约定

### 2.1 基础信息
1. Base URL：`/api/v1`
2. 数据格式：`application/json`
3. 时间格式：ISO 8601（示例：`2026-05-26T19:30:00+08:00`）
4. 单位约定：
   1. 距离统一存储为米（`distance_m`）
   2. 时长统一为秒（`duration_s`）
   3. 心率单位 bpm

### 2.2 认证约定（MVP）
1. MVP 允许匿名测试：通过请求头传 `X-Device-Id`
2. 后续可替换为 JWT：`Authorization: Bearer <token>`

### 2.3 响应包结构
成功：
```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

失败：
```json
{
  "code": 40001,
  "message": "invalid parameter: avg_hr_bpm",
  "data": null
}
```

### 2.4 错误码
1. `40001` 参数错误
2. `40004` 资源不存在
3. `40009` 业务校验失败（如峰值心率低于平均心率）
4. `40101` 未认证或认证失效
5. `42901` 请求频率过高
6. `50000` 服务器内部错误
7. `50021` OCR 解析失败
8. `50031` AI 报告生成失败

## 3. 数据模型（接口层）

### 3.1 运动记录对象 `SportRecord`
```json
{
  "record_id": "rec_01J0...",
  "user_id": "usr_01J0...",
  "sport_type": "running",
  "recorded_at": "2026-05-26T19:30:00+08:00",
  "duration_s": 1800,
  "distance_m": 5000,
  "avg_hr_bpm": 152,
  "peak_hr_bpm": 178,
  "rpe": 6,
  "note": "状态一般",
  "running_detail": {
    "pace_sec_per_km": 330,
    "cadence_spm": 172,
    "stride_cm": 105
  },
  "swimming_detail": null,
  "source": "manual",
  "created_at": "2026-05-26T19:50:00+08:00",
  "updated_at": "2026-05-26T19:50:00+08:00"
}
```

### 3.2 支持的枚举
1. `sport_type`：`running` | `swimming`
2. `source`：`manual` | `ocr`
3. `swim_style`：`freestyle` | `breaststroke` | `backstroke` | `butterfly` | `mixed`
4. `intensity_level`：`low` | `medium` | `high`

## 4. 接口定义

## 4.1 创建运动记录
`POST /api/v1/records`

请求体：
```json
{
  "sport_type": "running",
  "recorded_at": "2026-05-26T19:30:00+08:00",
  "duration_s": 1800,
  "distance_m": 5000,
  "avg_hr_bpm": 152,
  "peak_hr_bpm": 178,
  "rpe": 6,
  "note": "晚跑",
  "running_detail": {
    "pace_sec_per_km": 330,
    "cadence_spm": 172,
    "stride_cm": 105
  }
}
```

校验规则：
1. `duration_s > 0`
2. `distance_m > 0`
3. `peak_hr_bpm >= avg_hr_bpm`
4. `sport_type=running` 时必须传 `running_detail`
5. `sport_type=swimming` 时必须传 `swimming_detail`

响应：`SportRecord`

## 4.2 查询记录列表
`GET /api/v1/records`

查询参数：
1. `sport_type`（可选）
2. `start_date`（可选，yyyy-mm-dd）
3. `end_date`（可选，yyyy-mm-dd）
4. `page`（默认 1）
5. `page_size`（默认 20，最大 100）

响应：
```json
{
  "list": [],
  "pagination": {
    "page": 1,
    "page_size": 20,
    "total": 134
  }
}
```

## 4.3 查询记录详情
`GET /api/v1/records/{record_id}`

响应：`SportRecord`

## 4.4 上传截图并解析 OCR 草稿
`POST /api/v1/ocr/parse`

建议使用 `multipart/form-data`：
1. `image`：截图文件
2. `sport_type`：`running` | `swimming`

响应（草稿，不入库）：
```json
{
  "draft_id": "draft_01J0...",
  "sport_type": "running",
  "confidence": 0.88,
  "parsed": {
    "recorded_at": "2026-05-26T19:30:00+08:00",
    "duration_s": 1800,
    "distance_m": 5000,
    "avg_hr_bpm": 152,
    "peak_hr_bpm": 178,
    "running_detail": {
      "pace_sec_per_km": 330,
      "cadence_spm": 172,
      "stride_cm": 105
    }
  },
  "raw_text": "...OCR raw text...",
  "warnings": [
    "cadence_spm missing from screenshot area"
  ]
}
```

说明：该接口仅返回草稿，必须由前端确认后再调用创建记录接口入库。

## 5. 前后端联调建议
1. 第一批先联调：`POST /records`、`GET /records`、`POST /reports/generate`
2. 第二批联调：`POST /ocr/parse`（含草稿确认流）
3. 第三批联调：`GET /reports/weekly`、`POST /plans/generate`、`PUT /reminders/settings`

## 6. 测试样例建议
1. 正常跑步记录：5km，30min，心率区间正常
2. 异常心率记录：`peak_hr_bpm < avg_hr_bpm`，应返回 `40009`
3. OCR 缺字段：返回 `warnings`，允许用户补录
4. 高负荷连续训练：报告中应触发 `risk_alerts`

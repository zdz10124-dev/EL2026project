# 赛博教练需求文档（React 技术路线）

## 1. 项目概述
本项目面向校园场景，目标是让学生快速完成运动记录、得到 AI 分析建议，并形成持续的训练闭环。当前技术路线采用 React Web 优先，先在 PC 浏览器测试，再迁移到移动端。

## 2. 目标与边界

### 2.1 目标
1. 降低运动记录成本（手动 + 多模态截图解析）
2. 生成可理解的运动分析与建议
3. 建立周报与训练计划能力

### 2.2 边界
1. 非医疗建议，报告需附免责声明
2. 初期仅支持跑步与游泳
3. 多模态解析先覆盖少数高频截图，逐步扩展
4. 云端解析以结构化输出为主，避免仅返回自由文本

## 3. 用户与使用场景

### 3.1 目标用户
1. 校园学生（有运动计划或体测需求）
2. 需要低门槛记录与反馈的轻度运动人群

### 3.2 核心场景
1. 运动后手动录入数据
2. 上传运动截图由云端多模态解析生成草稿并确认
3. 查看单次报告与周报
4. 生成下一周训练计划

## 4. 功能需求

## 4.1 运动数据记录

### 4.1.1 记录方式
1. 手动录入
2. 截图上传 + 云端多模态解析 + 确认修正

### 4.1.2 支持运动类型
1. 跑步
2. 游泳

### 4.1.3 字段定义
通用字段：
1. 记录时间（datetime）
2. 运动时长（分钟，范围 1-600）
3. 运动距离（统一存储为米）
4. 平均心率（bpm，范围 30-230）
5. 峰值心率（bpm，范围 30-230）
6. 主观疲劳评分（1-10，可选）
7. 备注（可选）

跑步扩展字段：
1. 平均配速（每公里用时）
2. 平均步频（spm）
3. 平均步幅（cm）

游泳扩展字段：
1. 泳姿（自由泳/蛙泳/仰泳/蝶泳/混合）
2. 趟数
3. 平均配速（每 100 米用时）

### 4.1.4 校验规则
1. 距离和时长不能为 0
2. 峰值心率不能低于平均心率
3. 多模态解析结果必须确认后入库

## 4.2 运动记录分析与运动建议

### 4.2.1 分析流程
1. 将本次记录与历史数据打包上传云端
2. 云端多模态解析输出结构化结果，前端渲染固定区块

### 4.2.2 报告输出结构
1. 运动强度等级：低/中/高
2. 强度依据：心率区间、配速变化、时长完成度
3. 恢复建议：休息时长、拉伸建议、补水建议
4. 下一次运动建议：项目、时长、强度
5. 激励语：1-2 句，积极但不过度

### 4.2.3 风险提示
1. 连续高强度或恢复不足时提示
2. 显示非医疗免责声明
3. 记录图片与解析结果需标注来源与置信度

## 4.3 运动周报

最小可用要求：
1. 最近 7 天次数、总时长、总距离
2. 平均心率与强度分布
3. 2-3 条改进建议

验收标准：
1. 周一可查看上周报告
2. 失败时允许重试

## 4.4 训练计划

最小可用要求：
1. 用户设置目标与可用时间
2. 系统生成 7 天安排

验收标准：
1. 10 秒内生成
2. 支持一键重生成

## 4.5 训练提醒

最小可用要求：
1. 训练前提醒
2. 未完成训练补练提醒

验收标准：
1. 可开关提醒
2. 可配置提醒时间

## 5. 页面与交互（React Web）

### 5.1 页面列表
1. 登录页（可先做匿名模式）
2. 记录列表页
3. 新增记录页（手动）
4. 截图上传与识别确认页
5. 单次报告页
6. 周报页
7. 训练计划页

### 5.2 交互要点
1. 多模态解析草稿必须可编辑
2. 报告页固定三块：强度、恢复、下一次建议
3. 表单字段需展示单位

## 6. 技术路线要求（React）

1. 前端：React + TypeScript + Vite
2. UI：响应式布局，适配 PC 与 390px 宽度
3. API：按接口契约调用后端服务
4. 可扩展：后续可用 Capacitor 封装移动端

## 7. 非功能需求

1. 性能：列表页 1 秒内完成首屏
2. 可靠性：多模态解析或 AI 失败时提示并可重试
3. 可解释性：解析结果需提供字段级置信度或提示缺失字段
4. 安全：健康相关数据与截图最小化收集与加密存储
5. 合规：明确免责声明，不提供医疗诊断

## 8. 验收清单

1. 手动录入与编辑链路可用
2. OCR 草稿确认链路可用
3. 报告生成与展示完整
4. 周报可生成
5. 训练计划可生成
6. 提醒设置可保存

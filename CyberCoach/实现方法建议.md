# 赛博教练实现方法建议（PC 先测试，手机端后落地）

## 1. 建设目标
当前目标是先跑通核心业务闭环，再考虑移动端原生体验优化：
1. 运动记录（手动 + 截图）
2. 云端分析
3. 生成建议与报告
4. 周报和计划能力逐步上线

## 2. 技术路线总览
建议采用前后端分离，优先 Web 化开发：
1. 前端：React + Vite（响应式页面，先适配 PC 浏览器）
2. 后端：FastAPI（Python 生态便于 OCR 与 AI 调用）
3. 数据库：开发期 SQLite，稳定后迁移 PostgreSQL
4. 文件存储：本地存储或对象存储（开发期本地目录即可）
5. AI 与 OCR：OCR 引擎 + 规则解析 + 大模型纠错与建议生成

## 3. 分阶段实现

### 阶段 1：MVP（建议 1-2 周）
范围：
1. 手动录入跑步/游泳记录
2. 历史记录列表与详情
3. 运动报告生成（结构化输出）

完成标准：
1. 用户可以新增、查看、编辑记录
2. 每条记录都能生成报告
3. 页面在 PC 浏览器可稳定运行

### 阶段 2：截图识别（建议 1 周）
范围：
1. 上传截图
2. OCR 提取数据
3. 识别草稿确认页

完成标准：
1. 支持至少 2 类高频截图模板
2. 用户可确认并修正识别结果
3. 修正后数据可正常入库

### 阶段 3：周报与训练计划（建议 1 周）
范围：
1. 自动周报生成
2. 训练计划生成（按目标与时间约束）
3. 提醒开关与提醒时间配置

完成标准：
1. 可查看最近 7 天报告
2. 可生成下一周计划
3. 可配置并保存提醒策略

## 4. 后端核心模块建议

### 4.1 数据模块
建议最少包含以下数据表：
1. users：用户基本信息与目标
2. sport_records：运动通用记录
3. running_details：跑步专属字段
4. swimming_details：游泳专属字段
5. ai_reports：分析结果与建议
6. ocr_raw_logs：OCR 原始文本与解析过程

### 4.2 API 模块
建议优先实现以下接口：
1. POST /api/records：创建运动记录
2. GET /api/records：查询记录列表
3. GET /api/records/{id}：查询记录详情
4. POST /api/ocr/parse：上传截图并返回识别草稿
5. POST /api/reports/generate：生成单次运动报告
6. GET /api/reports/weekly：获取周报
7. POST /api/plans/generate：生成周训练计划

### 4.3 AI 模块
建议采用两段式处理：
1. 结构化计算：心率区间、强度等级、负荷趋势由规则引擎计算
2. 文案生成：建议与激励语由大模型生成，但必须基于结构化结果

收益：
1. 结果更稳定，便于测试
2. 降低大模型幻觉风险
3. 后续更容易做 A/B 测试和质量评估

## 5. 前端页面建议（PC 测试期）
最小页面集：
1. 登录页（可先做匿名模式）
2. 记录列表页
3. 新增记录页（手动输入）
4. 截图上传与识别确认页
5. 单次报告页
6. 周报页
7. 训练计划页

交互关键点：
1. OCR 结果必须可编辑，不允许直接提交不可改数据
2. 报告页固定展示强度、恢复建议、下次安排三大区块
3. 表单字段带单位提示，避免用户误填

## 6. 测试策略建议

### 6.1 功能测试
1. 手动录入与编辑流程
2. OCR 上传和解析流程
3. 报告生成结果完整性

### 6.2 数据质量测试
1. 心率异常值校验
2. 距离/时长为 0 的拦截
3. 峰值心率小于平均心率的拦截

### 6.3 AI 结果测试
1. 固定测试样例回归
2. 输出字段完整性检查
3. 风险提示触发正确性检查

## 7. 从 PC 到手机端的迁移建议
优先方案：复用 Web 前端并封装为移动应用。

路线：
1. 先完成响应式 Web（PC 和手机宽度都可用）
2. 使用 Capacitor 封装 Android/iOS 应用
3. 逐步接入移动端能力（通知、相册、摄像头）

优点：
1. 初期开发成本最低
2. 前后端接口可完全复用
3. 迭代速度快，适合验证产品方向

## 8. 风险与规避
1. OCR 准确率波动：先限制模板范围，逐步扩展
2. AI 建议不稳定：结构化规则前置，模型只负责语言组织
3. 数据隐私风险：图片和健康相关数据加密存储，最小权限访问
4. 功能范围失控：严格按阶段交付，不跨阶段提前堆需求

## 9. 建议的下一步
1. 先冻结 MVP 字段和接口
2. 先完成手动录入 + 报告生成端到端链路
3. 再接入 OCR 与周报功能
4. 最后推进训练计划与提醒

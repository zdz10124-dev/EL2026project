# 手机 App：赛博教练

## 一、需求定位
这是一个面向校园场景的 AI 运动记录与教练 App，核心目标不是替代专业医疗或体能教练，而是帮助学生把“运动记录、效果分析、计划制定、持续跟踪”串成一个闭环，让运动更容易坚持、更容易量化。

校园场景下，这个需求是合理的，原因主要有三点：
+ 学生群体运动频率不稳定，缺少持续监督和反馈，AI 能降低记录和分析成本。
+ 校园运动常见于跑步、健身、球类、体测训练等，数据类型相对标准化，适合做轻量化识别和分析。
+ 学生对“个性化计划”和“可视化进步”接受度高，报告和建议更容易形成持续使用动机。

## 二、实现可行性
整体上可分为“高可行、分阶段落地”的产品。

### 1. 可直接落地的部分
+ 手动录入运动记录：时长、项目、距离、组数、配速、心率、消耗等。
+ 图像识别辅助录入：识别跑步截图、运动手环截图、体测结果截图、打卡截图等。
+ 基于规则和大模型的运动总结：对单次运动进行文字总结、强度判断和建议生成。
+ 历史数据统计：周/月趋势、累计次数、平均训练时长、稳定性分析。

### 2. 需要分阶段实现的部分
+ 运动计划自动制定：需要先明确用户目标、基础体能、每周可用时间和限制条件。
+ 定期报告自动生成：需要后台定时任务、模板化报告和用户推送机制。
+ 图像识别高准确率：不同截图来源差异较大，建议先支持少数高频模板，再逐步扩展。

### 3. 需要注意的约束
+ 涉及健康建议时要明确免责声明，避免替代医生诊断。
+ AI 建议应优先做“辅助决策”，而不是完全自动控制用户训练强度。
+ 校园用户对隐私较敏感，运动数据、身体数据和图片需要明确授权与加密存储。

## 三、完善后的具体功能描述

### 1. 用户信息与目标管理
+ 用户基础资料：年龄、性别、身高、体重、运动基础、常用运动类型。
+ 运动目标设置：减脂、增肌、提升体能、改善心肺、体测备考、保持习惯等。
+ 约束条件设置：每周可训练次数、单次可用时长、是否有伤病史、是否适合高强度训练。

### 2. 运动记录采集
+ 手动记录：用户可填写运动类型、时间、距离、组数、配速、心率、备注等。
+ 图像识别录入：上传运动截图、表单截图或成绩单图片，自动提取关键数据并生成记录草稿。
+ 记录修正：识别结果支持人工确认和修改，避免错误数据直接进入分析。
+ 多来源汇总：支持将手环、跑步 App、拍照记录与手动记录统一到个人运动档案中。

### 3. 运动效果分析
+ 单次分析：基于本次记录判断运动强度、完成度和恢复建议。
+ 阶段分析：按周、按月查看运动频率、总量、提升幅度和波动情况。
+ 个性化分析：结合用户目标和历史表现，判断当前计划是否过强、过弱或需要调整。
+ 风险提示：当系统发现连续高强度、恢复不足或异常下降时，提示降低训练强度或休息。

### 4. AI 运动建议与计划制定
+ 自动生成周训练计划：根据目标、时间安排和当前水平推荐训练日程。
+ 动态调整计划：当用户漏练、超量或状态变化时，自动给出替代训练或降阶方案。
+ 训练内容推荐：提供有氧、力量、拉伸、恢复训练等组合建议。
+ 校园适配方案：支持宿舍、操场、健身房、教室间隙等不同场景下的轻量训练建议。

### 5. 报告与反馈
+ 单次运动报告：展示本次训练内容、完成情况、消耗估算和下一步建议。
+ 周报/月报：汇总趋势、进步点、薄弱项和持续改进建议。
+ 可视化呈现：用图表展示训练次数、时长、强度分布、目标达成率。
+ 任务反馈：将“今日训练完成”“本周目标完成”等结果以简洁卡片形式反馈给用户。

### 6. 定期提醒与陪伴
+ 训练提醒：按计划推送训练提醒和补练提醒。
+ 报告推送：定期生成并推送阶段报告。
+ 激励机制：连续打卡、目标达成、阶段提升可获得徽章或成就反馈。

## 四、建议的产品边界
+ 第一版优先做“记录 + 分析 + 建议 + 周报”，避免一开始就做过重的算法训练。
+ 图像识别先覆盖 2 到 3 类高频场景，例如跑步截图、体测成绩截图、运动打卡截图。
+ 计划制定先采用“规则模板 + AI 文案生成”的组合方式，后续再升级为更智能的动态计划引擎。

## 五、结论
这个需求方向合理，且适合校园场景落地。最稳妥的实现路径是先做轻量记录和 AI 分析，再逐步扩展到自动计划和长期陪伴型功能，这样能兼顾开发成本、识别准确率和用户体验。

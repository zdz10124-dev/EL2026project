# 比赛演示脚本

## 建议时长：4 分钟

1. **定位（20 秒）**：说明用户通常需要在饮食、运动和健康建议三个应用之间切换，本项目将它们放入一个可追溯闭环。
2. **饮食记录（40 秒）**：进入“记录 -> 饮食”，展示拍照、AI 识别、人工确认后保存，强调本地保存不等待网络上传。
3. **运动记录（60 秒）**：进入“记录 -> 运动”，选择跑步，上传运动 App 截图，执行 AI 识别，展示时长、距离、心率和热量自动填入但仍可修改，再保存。
4. **今日视图（30 秒）**：返回“今天”，展示今日餐次数、运动分钟数、快捷记录入口和缓存中的今日建议。
5. **综合分析（70 秒）**：进入“健康 -> 综合健康分析”，切换 7 天和 30 天，展示本地确定性指标、饮食/运动/休息建议及每条建议的 evidence。
6. **可信边界（30 秒）**：演示数据不足、AI 未配置或网络失败状态，以及非医疗建议声明和旧缓存标识。
7. **总结（30 秒）**：强调创新点是多模态记录、跨领域关联、确定性计算与 AI 分工、证据可追溯，而非简单增加一个聊天机器人。

## 演示前检查

- 可在“我的 -> 导入比赛演示数据”一键生成脱敏记录，重复导入不会重复添加。
- 服务端已配置 `OPENAI_API_KEY`、`OPENAI_BASE_URL` 和可选的 `OPENAI_MODEL`。
- 客户端已登录服务端模式，或已配置直连开发模式。
- 预先准备至少两天的饮食或运动记录，确保综合分析可生成。
- 运动截图不包含姓名、账号、定位轨迹等隐私信息。
